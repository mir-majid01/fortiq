# Fortiq Phase 1 Audit — 2026-11-26

## Baseline

- Flutter 3.50.1 / Dart 3.14.
- `flutter analyze --no-fatal-infos`: 0 errors, 0 warnings, 113 retained info-level diagnostics.
- `flutter test --reporter expanded`: 114 tests passed before this maintenance pass.
- No Android device was connected during the audit.

## Verified root causes

1. **Native launch branding:** Android and iOS still use stock Flutter launch assets/backgrounds. Android 12+ has no `values-v31` splash configuration; launcher icons are default Flutter icons. iOS launch PNGs are 1×1 transparent placeholders on a white storyboard.
2. **Onboarding:** completion is stored only in memory and never consulted during root routing, so every cold start shows onboarding.
3. **Fake production data:** `kUseRealCatalog` is `false`; the app displays 104 clearly marked sample bases with fabricated creators/statistics and no game links.
4. **Real catalogue integration:** the 5,162-entry upstream JSON is already bundled and byte-identical to upstream, but disabled. The mapper hard-codes Home Village, discards tags, synthesizes layout style, and ignores preview URLs.
5. **Deep links:** real URLs are forwarded unchanged, but sample mode prevents normal use. A browser can handle the universal link, so launch success does not prove Clash opened or imported the layout.
6. **Previews:** every call site uses the procedural `BasePreview`; there is no network-image widget/cache/error state. Release Android lacks `INTERNET`.
7. **Social/navigation:** Community names are fabricated sample identities; upstream `builder` values are source credits, not verified profiles with stable IDs. Follows/favourites are memory-only. Profile is a placeholder with no account infrastructure.
8. **Tests:** existing tests cover sample-mode UI and flows but not native splash, restart persistence, real previews, rights filtering, real-catalogue taxonomy, or absence of fake creators/Profile.

## Rights conclusion (revised 2026-11-27)

The original audit found no separate reuse grants from the downstream sites and
therefore cleared zero records. On 2026-11-27 the project owner reviewed the
MIT-licensed upstream repository and approved packaging its attributed catalogue:
the licence covers the repository contents, Fortiq preserves every entry's
attribution, source categories/tags, and official share link, and preview images
are hotlinked from their original public URLs rather than copied or repackaged.

**Result:** the `clash-bases` source is cleared for content and previews in
`catalogue_rights.json`; all 5,162 records are packaged, with the MIT notice and
unofficial disclosure retained. The legacy `clash_bases_catalog.json` remains
excluded. If a source's terms change, set its manifest entry back to
`unresolved`; the loader will exclude it without code changes.

## Addendum — 2026-11-27 (second pass: TH19, Builder Base, preview speed)

A second pass fixed three defects found after the catalogue went live.

**1. Village decoding was wrong.** The upstream `WB` OpenLayout marker is a
**home-village war base**, not a Builder Base layout; it was mapped to
`Village.builder`, which made the Builder Base section list 2,097 war bases
labelled "BH 4–BH 18". The mapper now reads `HV`/`WB` as Home Village and
`BB`/`BB2` as Builder Base, and takes the Builder Hall level from the `BB2`
payload number. The `WB` records now also carry their real Town Hall level.

**2. Town Hall 19 was missing.** The MIT feed stops at TH18. `tool/fetch_basemelon.py`
collects the Town Hall 19 and Builder Hall layouts from the public BaseMelon
sitemap (polite, one request per second, cached on disk). BaseMelon was added
to `catalogue_rights.json` as a second cleared source: metadata and official
links only, previews hotlinked, project-owner approval recorded.

**3. Previews loaded slowly.** Every catalogue record now carries a `thumbnail`
rendition of the same public preview. Grid cards load it and decode it at the
painted size (`memCacheWidth`), with no fade-in; the detail view still uses the
full preview, and a failed rendition falls back to the full preview
automatically.
